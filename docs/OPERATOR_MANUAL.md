## 1. การเข้าสู่ระบบครั้งแรก

เมื่อระบบติดตั้งเสร็จสิ้น DataSeeder จะสร้างบัญชี Super Admin เริ่มต้น:
- **URL:** `http://<YOUR_SERVER_IP>/login`
- **Username:** `admin`
- **Default Password:** `AdminPassword@123`

> [!IMPORTANT]
> **คำแนะนำด้านความปลอดภัย:**
> เมื่อเข้าสู่ระบบสำเร็จในครั้งแรก ให้ไปที่เมนู **Users** ทันที เพื่อเปลี่ยนรหัสผ่านของ `admin` เป็นรหัสผ่านที่มีความซับซ้อน (อย่างน้อย 12 ตัวอักษร ประกอบด้วยตัวพิมพ์ใหญ่ พิมพ์เล็ก ตัวเลข และอักขระพิเศษ)

## 2. การจัดการผู้ใช้และบทบาทสิทธิ์

ผู้ดูแลระบบสามารถสร้างและจัดการผู้ใช้งานได้ตามลำดับสิทธิ์:

| บทบาท (Role) | สิทธิ์การเข้าถึง | หน้าที่ที่เหมาะสม |
| :--- | :--- | :--- |
| **ROLE_SUPER_ADMIN** | สิทธิ์สูงสุดในระบบทั้งหมด | หัวหน้าทีม System Engineer / CISO |
| **ROLE_ADMIN** | จัดการ Vault, สร้าง/แก้ไข Pipeline, จัดการ Task | DevOps Engineer, Database Administrator |
| **ROLE_OPERATOR** | สั่ง Trigger Pipeline, Pause/Resume, สั่ง Abort, ดู Console | NOC Team, IT Operations |
| **ROLE_VIEWER** | ดูประวัติการรัน, ดูสถานะ Dashboard (Read-Only) | Management, Compliance Auditor |

### มาตรการป้องกัน Brute-Force (Account Lockout)
- หากผู้ใช้กรอกรหัสผ่านผิดติดต่อกัน **5 ครั้ง** บัญชีจะถูกล็อคอัตโนมัติเป็นเวลา **15 นาที**
- ผู้ดูแลระบบ (Super Admin) สามารถเข้าไปที่หน้า **Users** เพื่อกดปลดล็อค (Unlock) บัญชีได้ทันทีโดยไม่ต้องรอหมดเวลา

## 3. การจัดเก็บข้อมูลลับใน Vault

Custos ป้องกันการเก็บ Plaintext Password ในระบบเด็ดขาด โดยข้อมูลทั้งหมดจะถูกเข้ารหัสผ่าน **AES-256-GCM**

1. ไปที่เมนู **Credentials (Vault)**
2. คลิกปุ่ม **+ New Credential Profile**
3. เลือกประเภท Credential:
   - `DATABASE_MYSQL`: สำหรับเชื่อมต่อสำรองข้อมูล MySQL / MariaDB
   - `DATABASE_POSTGRESQL`: สำหรับเชื่อมต่อสำรองข้อมูล PostgreSQL
   - `STORAGE_SFTP`: สำหรับเชื่อมต่อส่งไฟล์ผ่าน SSH / SFTP (รองรับทั้ง Password และ SSH Private Key)
   - `STORAGE_FTP`: สำหรับเชื่อมต่อ FTP / FTPS
4. กรอก Host, Port, Username, และ Password หรือวาง OpenSSH Private Key
5. กดปุ่ม **Test Connection** เพื่อทดสอบความถูกต้องก่อนบันทึก

## 4. การออกแบบ Pipeline

Custos มีหน้าจอ **Visual Pipeline Builder** ที่พัฒนาด้วย **React Flow (`@xyflow/react`)**:

### ขั้นตอนการสร้าง Workflow:
1. ไปที่เมนู **Pipelines** -> แท็บ **Visual Builder**
2. ลาก Step Nodes จากแถบเครื่องมือลงบน Canvas:
   - **Database Backup:** กำหนด Credential และชื่อฐานข้อมูลที่ต้องการ Dump
   - **File Backup:** กำหนดโฟลเดอร์ต้นทาง และรูปแบบการบีบอัด (`TAR_GZ`, `ZIP`, `TAR_ZSTD`)
   - **Split Transfer:** กำหนดขนาด Chunk (เช่น 100MB, 500MB) และ Credential ปลายทาง
   - **Email Alert:** กำหนดผู้รับอีเมลแจ้งผล
3. **การลากเส้นเชื่อมโยง (Edges):**
   - ลากจาก Handle สีเขียว (จุดขวาของโหนด) เพื่อกำหนด **On Success Path** (เส้นทึบสีเขียว)
   - ลากจาก Handle สีแดง (จุดล่างของโหนด) เพื่อกำหนด **On Failure Path** (เส้นประสีแดง)
4. **การส่งต่อผลลัพธ์ข้าม Step (Context Passing):**
   - สามารถใช้ตัวแปร `${last_output_path}` เพื่อนำไฟล์ที่ Dump ได้ใน Step แรก ส่งต่อไปยังโหนด Split Transfer ใน Step ถัดไปโดยอัตโนมัติ

## 5. การตั้งเวลาการทำงานอัตโนมัติ

1. ในหน้า Pipeline Builder สามารถกำหนด **Cron Expression**:
   - `0 0 2 * * ?` -> รันทุกวันเวลา 02:00 น.
   - `0 0 12 ? * SUN` -> รันทุกวันอาทิตย์เวลา 12:00 น.
2. เลือก **Timezone** (เช่น `Asia/Bangkok`, `UTC`)
3. เลือก **Misfire Policy**:
   - `SMART_POLICY`: ให้ Quartz เลือกนโยบายที่เหมาะสมที่สุด
   - `FIRE_NOW`: หากเซิร์ฟเวอร์เพิ่งกลับมาทำงาน ให้รันรอบที่ตกค้างทันที 1 ครั้ง
   - `DO_NOTHING`: ข้ามรอบที่ตกค้างและรอรันในรอบถัดไปตามเวลาปกติ

## 6. การติดตามการทำงานแบบสด

หน้าต่าง **Live Console Terminal** ใช้ WebSocket STOMP สตรีมมิ่งข้อความ Log บรรทัดต่อบรรทัด:

- **สถานะการเชื่อมต่อ:** แสดง Badge `LIVE STREAM` สีเขียวกระพริบเมื่อเชื่อมต่อสำเร็จ
- **Auto-scroll:** หน้าต่างจะเลื่อนลงบรรทัดล่างสุดอัตโนมัติ (สามารถติ๊กถูกออกเพื่อหยุดเลื่อนและอ่าน Log ที่ผ่านมา)
- **Log Search & Level Filter:** พิมพ์ข้อความเพื่อค้นหา หรือคลิกปุ่มกรองเฉพาะ `ERROR`, `WARN`, `INFO`
- **Chunk Progress Bar:** หากงานนั้นมีกระบวนการโอนย้ายไฟล์ จะแสดง Progress Bar แสดง % ความคืบหน้า, จำนวน Chunk ที่ส่งสำเร็จ, และปริมาณ Byte แบบ Real-time
- **Copy & Clear:** ปุ่มคัดลอกข้อความ Log ทั้งหมดลง Clipboard เพื่อส่งวิเคราะห์ต่อ

## 7. ระบบแจ้งเตือนผ่านอีเมล

เมื่อ Pipeline ทำงานเสร็จสิ้น Custos จะส่งอีเมลรายงานผลผ่าน **AWS SES**:

### 1. อีเมลสรุปความสำเร็จ (Pipeline Success Summary)
- ระบุชื่อ Pipeline และเวลาที่ใช้ประมวลผลทั้งหมด
- ขนาดไฟล์รวมที่สำรอง และค่า **SHA-256 Checksum** สำหรับตรวจสอบความถูกต้อง
- จำนวน Chunks ที่ถูกแบ่งและส่งต่อไปยังเซิร์ฟเวอร์ปลายทาง

### 2. อีเมลแจ้งเตือนข้อผิดพลาด (Pipeline Failure Alert)
- ระบุ Step ที่ล้มเหลว และ Exit Code ของระบบ
- คำอธิบายสาเหตุข้อผิดพลาด
- **แนบ 50 บรรทัดสุดท้ายของ Log** ในกล่อง Code Block เพื่อให้วิเคราะห์ปัญหาได้ทันทีโดยไม่ต้องเปิดเซิร์ฟเวอร์

## 8. การตรวจสอบบันทึกความปลอดภัย

ไปที่เมนู **Audit Logs** เพื่อตรวจสอบกิจกรรมของผู้ใช้ทุกคนในระบบ:
- บันทึกการ Login สำเร็จ, Login ผิดพลาด, และการล็อคบัญชี
- บันทึกการเพิ่ม แก้ไข หรือลบ Credential ใน Vault
- บันทึกการสร้าง ปรับปรุง หรือลบ Pipeline
- บันทึกผู้สั่งรันงาน (Triggered By) และการสั่ง Abort งาน
- ทุก Record บันทึก IP Address และ User Agent ของเครื่องต้นทางอย่างละเอียด

## 9. การแก้ไขปัญหาและการหยุดงานฉุกเฉิน

### 1. การสั่งหยุดงานฉุกเฉิน (Emergency Abort)
หากพบว่า Pipeline กำลังทำงานผิดพลาด หรือคำสั่งค้าง:
- ไปที่หน้า **Live Console** หรือ **Pipelines -> History**
- คลิกปุ่ม **Abort Execution** (ไอคอนสี่เหลี่ยมสีแดง)
- ระบบจะทำการส่งสัญญาณยกเลิก Process OS ทันที และทำความสะอาด Temporary Chunks ใน Staging

### 2. ข้อผิดพลาด Checksum Mismatch
- ตรวจสอบว่าเครือข่ายปลายทางมีความเสถียรหรือไม่
- ตรวจสอบว่า Disk ปลายทางไม่เต็ม (ระบบมี Storage Pre-check ตรวจสอบก่อนเริ่มงานเสมอ)
- ระบบ Custos มีกลไก **Auto-Retry** เฉพาะ Chunk ที่หลุด สูงสุด 3 ครั้ง หากยังไม่สำเร็จจึงจะหยุดและแจ้งเตือน
